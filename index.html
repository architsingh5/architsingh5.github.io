01 · Exchange

A trade prints on the exchange

Orders and executions arrive from ICE EU and NYMEX at peak-hour volume. Everything downstream has to keep up: orders, executions, clearing.

the start of the trade lifecycle

02 · Ingestion

Striped across three hosts

Instead of one primary host taking all the flow, I striped ICE EU and NYMEX traffic across three load-balanced hosts, so a busy market no longer means one hot machine.

54% / 64%less load on the primary host, with steady throughput at peak

03 · Kafka

Onto the backbone

Each trade becomes an event on Kafka topics. A transactional outbox commits the state change and the event together, so downstream services never miss a trade.

Outboxreliable delivery between services

04 · Hydration

Hydrated for every reader

Java/Kafka Data Hydration pipelines publish the trade twice: to a GCP-backed OLTP store for live lookups and to a Snowflake lakehouse for analytics.

OLTP + OLAPone pipeline feeding both kinds of store

05 · Controls

Checked, mapped, reconciled

DB2-based controls reconcile what landed against the source. The firmwide mapping rules that classify each trade are now read from a database instead of static definitions, so changing a rule no longer takes a week.

7d → 1drule-change turnaround

06 · Reporting

Out the other side

Broker reports for the Korean and South African markets reconcile executions against client orders over TIBCO RV and run on an interval. Dashboards that read the data are now much faster.

75%faster dashboard responses after query-path profiling
